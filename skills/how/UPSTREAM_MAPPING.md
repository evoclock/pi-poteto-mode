# Source-name mapping and Pi execution boundary

Read this file with WORKFLOW_BOUNDARIES.md before following a retained source procedure. The procedure is pstack 0.15.36, Lauren Tan (MIT); UPSTREAM.lock.json at the package root records source hashes. Preserved wording is not a grant to run its commands. Pi boundary blocks constrain effects while keeping the original checklist reviewable.

## Resolve source names

- A source skill named `X` resolves to this package's `skills/X-pi/SKILL.md`. `/X` becomes `/skill:X-pi` only when the installed Pi manifest registers it. This includes principle leaves. Do not call an unrelated same-name skill accidentally.
- From a skill root, a source link `../X/SKILL.md` means `../X-pi/SKILL.md`. From nested references, preserve the source-relative internal reference path; cross-skill paths still map the skill directory to its `-pi` directory.
- Source `playbooks/<slug>.md` resolves under `skills/poteto-mode-pi/playbooks/`. The index file is not the procedure. Copy source steps verbatim, then add Pi boundary notes and retained skip reasons. Fenced examples are not new task steps.
- Source `pstack/skills/X/...` resolves under this package's `skills/X-pi/...`. Supporting prose is bundled; executable upstream scripts and agent definitions are not. A missing helper is blocked, not an invitation to fetch or install it. The shared safety documents are under `skills/how/`, not a second registered how skill.
- The source may mention external plugins, a control skill, a renderer or a built-in authoring tool. Resolve only an installed, separately approved Pi equivalent. No such tool is supplied by a skill name or by an illustrative source command.

## Resolve roles and state

- Source model/provider names and fallback slugs are historical source text, never Pi model selection. Read exact approved identities from the project-local `.pi/pstack-model-roles.v1.json` via setup-pstack-pi. Current schema supports development and independent-review. Extra panel seats, different-family requirements and budget controls need a separately configured route. Missing roles/capacity leave those phases blocked; no parent-model fallback or silent provider substitution.
- Cursor Task/subagent types and cloud flags map to Pi processes in Herdr panes, not CloudAgent. First acquire a checkout with `treehouse get --lease --json --base <verified-ref>`; use its path as `worktreePath` in `agentic_herdr_spawn_worker` with `placement: "tab"`, the trusted repository registry name, a safe role name and the exact approved model. Inspect existing roles with `agentic_herdr_communication` action `list`. A source `environment: "cloud"` field is not passed to Pi tools; actual isolation requirements must still be met.
- Give each worker one bounded brief with `agentic_herdr_communication` action `prompt`/`submit`, then inspect `delivery` and `read` without resending. For a configured session-task role use `agentic_worker_dispatch_async` submit then poll/observe/read. Use `agentic_worker_dispatch` pulse or read-only artifact/PR observations for liveness, never resume a worker to probe it. An unavailable independent review is unrun, not a self-review pass; delivery receipts are not answers.
- Use `TaskList`, `TaskCreate` with priority, and `TaskUpdate` for source todolists. Keep the source steps word for word; attach boundaries and skipped-step reasons separately. If no task tool exists, report the unsupported checklist operation and preserve a local checklist only when its path is approved.
- Read only named authorized transcripts and accepted ranges in the active workspace. No global private-chat search. Source home-directory rules, scratch paths and credential commands are not Pi destinations. Scratch stays in the approved repository, never an OS temporary directory.

## Effect and evidence boundary

Shipping and merge phases remain owner-held even when upstream tells an agent to merge. Autopilot-full may build and verify within its grant but stops before landing. The automatic Opening a PR tail is a checklist/handoff; actual publication needs the task's approved repository, branch and content boundary. Independent verification, current patch coverage and operator gates still apply. See docs/adaptation-guide.md, Policy divergences.

Run only installed, approved commands. Every dependency install is an explicit top-level Socket Firewall operation, never embedded in a helper or triggered by retained source prose. Do not copy upstream bootstrap installers. Preserve failed/uncertain work and explain missing capability; do not fabricate a runtime proof to finish a source checklist.

On macOS the statechart Pi path is `node <statechart-pi-dir>/scripts/run-tlc.mjs --check`, then explicit `--spec`, `--config` and a new `--out` directory inside repository `.scratch/`. The adapter invokes only installed `tlc` on PATH or a selected existing `TLA2TOOLS_JAR` with Java on PATH; no mise/download/first-run install. A missing checker is blocked. Its self-installing upstream chart runtime is not bundled. Mermaid and diagrams are views only, never a TLA+ proof. Ketchup-video is planned and not registered; use text catch-up while no validated render-and-inspection route exists. Neither reading this mapping nor installing this skills package changes Pi defaults, grants authority, or proves live loading.
