# Boundaries for the reviewed engineering skills

Read this file whenever using any skill in this package.

- A skill provides a method, not execution authority. Follow the agreed repository, paths, model/data route, resource bounds, acceptance and stopping point. Escalate missing permission, consequential design changes, ambiguous effects and unresolved acceptance failures; continue ordinary scoped work without repeated approval requests.
- Search the code before new authorship. Read actual source and reuse existing tools. Complexity and duplication are diagnostic signals, not mandatory rejection thresholds.
- Agree BDD-style observable success and failure scenarios first. TDD may help a small deterministic regression; do not impose a new test framework. Scientific results need independent expected values/oracles.
- Use Treehouse for new checkouts: run `treehouse get --lease --json --base <verified-ref>` from the approved repository and retain the returned path/lease. Do not create plain worktrees. Start each writing Pi agent in its own leased checkout; a lease is not runtime containment. If Treehouse or required isolation is unavailable, mark that step blocked rather than substituting a cloud agent or unmanaged checkout.
- Use the project's existing task tracking. Session tasks track session work; they do not authorize implementation. Do not mark tracked work complete from worker reports alone or introduce another scheduler.
- Before any model-role-dependent work, read the project-root `.pi/pstack-model-roles.v1.json` created through `/skill:setup-pstack-pi` (shape: `../setup-pstack-pi/assets/pstack-model-roles.v1.example.json`). Require schema `pstack-model-roles.v1` and nonempty exact Pi model identities for the needed `development` and `independent-review` roles. If the file or needed role is missing or malformed, report `pstack role <role> is not configured at .pi/pstack-model-roles.v1.json; run /skill:setup-pstack-pi` and stop that workflow. Do not infer a role from a skill, current session or placeholder. A direct read-only method that uses no model role need not be blocked by an unused role.
- For delegated work, use configured Pi roles in Herdr panes through `agentic_herdr_spawn_worker`, then bounded briefs and reports through `agentic_herdr_communication`. Use only the installed route within the model/data grant. Check that a model author actually matches the configured development role and that the resolved reviewer identity matches the configured independent-review role and differs from the author; if identity, availability or grant cannot be checked, stop the independent-review claim and report the gap. No automatic fallback or profile change. A role map is data, not a Pi setting or authorization. Receipts prove submission/delivery, not answers or authority. Make one observation per requested poll; never blindly resend accepted work.
- No agent-invented provider/model defaults, automatic cloud escalation, broad MCP discovery, private-chat scanning or unapproved transcript access. Request access to named files and a limited data range if necessary. No secret values in commands, evidence, logs or commits; approved platform secret stores remain authoritative.
- No destructive shell/interpreter/disk/database/forge actions, reset/force push or automatic disposal. Preserve failed/superseded work through approved archival. Workspace cleanup follows verified human merge confirmation; generic sandbox wipe/volume disposal is not implied.
- Scope commits and review-branch delivery to the verified, explicitly approved repository. Only the repository owner merges. Agents never merge a PR, including an independently reviewed PR. A suffix alone grants nothing. A direct accepted task may authorize a public review branch and PR after outgoing-content inspection; the skill itself never supplies that grant. Package publication and releases remain separately owner-held.
- Save sanitized decision/review evidence in an approved version-controlled path. Private corpus/cache representation remains an owner decision. An ignored file is not version-controlled evidence; do not force-add private content or change ignore rules to bypass this. Do not use OS temporary directories.
- Pin reviews to exact base/head or identified dirty artifact; later edits invalidate affected findings. Reports distinguish source inspection, tests actually run, proposed tests, runtime proof and owner acceptance.
- Extend the owner's existing handover with approved evidence pointers and unresolved items. Do not create a competing handover system. Do not run its broad survey/fetch/pruning instructions implicitly.

## Concrete Pi/Herdr route

- Use `TaskList`, `TaskCreate` (with priority) and `TaskUpdate` for the existing session checklist. Copy the source steps verbatim, attach Pi limits separately and keep blocked/skipped steps visible. These are not Cursor Task calls and do not spawn workers.
- Observe configured Herdr roles with `agentic_herdr_communication` action `list`. Reuse a suitable configured non-coordinator role, or start one with `agentic_herdr_spawn_worker`: `placement: "tab"`, a safe role name, its exact approved model, the trusted repository registry name and the Treehouse `worktreePath`. Verify that the registry repository matches the accepted repository. Names or receipts create no authority; do not run raw pane/terminal-management commands or CloudAgent.
- Submit one bounded brief with `agentic_herdr_communication` action `prompt` or `submit`. Use `delivery` to inspect that handoff and `read` for a report; do not resend a delivered prompt. For configured session-task exchanges, `agentic_worker_dispatch_async` provides `submit`, then `poll`/`observe`/`read`. `agentic_worker_dispatch` action `pulse` observes liveness. Reports and delivery receipts are evidence, not proof the work ran correctly.
- Board cards are separate: use `agentic_kanban_pulse` check for observation; only an existing approved board policy permits `agentic_kanban_board_dispatch`. Neither a skill nor a session-task dispatch claims a board card. Never invent a second scheduler or board writer.
- Replace cloud verifiers with independent Pi verifiers in Herdr panes on Treehouse leases, using the configured independent-review identity and a different family where the source requires it. Brief the exact patch, parent/head, user goal and real control-surface check. Inspect outputs/artifacts and rerun reported repros. A Pi pane is not a cloud VM; missing isolation, family diversity or surface access makes that check blocked, not a self-review pass.
- Use the installed GitHub CLI for this Pi mapping: `gh repo view --json nameWithOwner,visibility,viewerPermission`, `gh pr view <pr> --json headRefOid,baseRefName,url`, `gh pr diff <pr>` and `gh pr checks <pr>`. For authorized review-branch delivery use `git push` and `gh pr create`/`gh pr edit`, then read back `gh pr view`. Source Origin preferences do not require Origin on Pi. No merge, auto-merge or force-push is imported.
- Cursor `/loop` maps only to an already configured bounded driver journey or an approved host wake mechanism. With no such mechanism, report background wake/watch unsupported and perform only the granted single status pass. Never emulate it with a new sleep loop. Keep the Treehouse lease for failed, unmerged or uncertain work; return it only after owner-confirmed integration and reconciliation.

GPU/CUDA stacks remain untouched. This bundle does not enable global loading, change settings, install dependencies, spawn agents or authorize live tests merely by being read.
